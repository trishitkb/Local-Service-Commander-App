Windows System Utility · Offline-First

Local-first service and process control center for Windows.

Local Service Commander detects installed databases, development runtimes, web servers, and background daemons running on the machine. It provides a centralized dashboard for real-time telemetry, port conflict resolution, guarded process termination, and custom stack orchestration without requiring an IDE or terminal.

Core System Architecture
Engineered for Reliability, Safety & Speed
Zero simulated data. Every metric and socket binding reflects actual Windows OS kernel and network states.
01 / DISCOVERY

Automated Detection Engine

Continuously queries Windows management instrumentation (WMI) and active process tables to identify PostgreSQL, MySQL, Redis, Docker, Node.js, Python, Java, and .NET daemons with zero manual configuration.

02 / TELEMETRY

Kernel-Level Resource Metrics

Accurate CPU utilization percentages, resident working set memory (RAM), thread counters, and process identifiers (PID) refreshed continuously via high-efficiency Windows system calls.

03 / SAFETY

Protected-Process Guards

Explicit confirmation modals protect against accidental service interruption. System-critical binaries (LSASS, CSRSS, SMSS, WinInit) and low PID allocations are blocked from termination.

04 / CUSTOMIZATION

Custom Process Registry

Register project-specific start/stop scripts (e.g., npm run dev or cargo run) directly in Commander. Definitions persist in %APPDATA% across reboots and closures.

05 / ORCHESTRATION

Multi-Process Collections

Group dependent services (e.g., Database + API Server + Frontend Dev Server) into named Collections. Launch or terminate an entire development environment with a single action.

06 / NETWORKING

TCP Port Matrix & IPC Inspector

Comprehensive table of all active listening sockets on the host machine. Identifies owning PIDs, bound IP addresses, socket states (LISTEN / ESTABLISHED), and active client connection counts.

System Architecture
Three-Tier Decoupled Architecture
Engineered for security, high responsiveness, and zero external runtime dependencies.
Data Flow & Process Boundary
+----------------------------------------------------+ | Tauri 2 Native Host (Rust x64) | | WebView2 UI Context (React 19 + TypeScript) | +----------------------------------------------------+ | HTTP REST / 127.0.0.1:4174 v +----------------------------------------------------+ | Commander Local API Sidecar (Compiled Binary) | | - Process Scanner (wmic / Win32_Process) | | - Socket Telemetry Engine (netstat -ano) | | - Process Tree Manager (taskkill / spawn) | | - Persistent Preferences (%APPDATA%) | +----------------------------------------------------+ | Windows Kernel / OS APIs v [ Redis ] [ PostgreSQL ] [ Vite ] [ Custom Daemons ]
Security & Operational Boundaries
  • Strict Local Binding: The internal companion API binds exclusively to the loopback interface (127.0.0.1:4174). It does not listen on 0.0.0.0 and cannot be accessed over local area networks.
  • No Elevation Requirement: Standard process inspection and discovery operate entirely under normal user privileges without requiring UAC administrator prompts.
  • Zero Cloud Connectivity: No analytics, crash reporting, telemetry, or external API calls are dispatched. Complete functionality is maintained in air-gapped environments.
  • Tree Termination: Stopping managed services utilizes Windows taskkill.exe /PID <pid> /T /F to ensure all spawned child worker threads are terminated cleanly without leaving orphaned processes.
